# AX3600 刷机前准备清单（Wi-Fi 环境版）

> 你的场景：电脑只能连 Wi-Fi，路由器后台进得去但**没有外网**。
> 先说结论：**刷机能做，但缺少网线是本流程唯一的硬风险点**，见第 2 节。

---

## 1. 最关键的认知：我无法远程连你的路由器

我在你电脑上运行，**不在你家里那个局域网里**，所以 `ssh root@192.168.31.1` 我这边是连不上的。
实际分工是：

- **我负责**：生成命令/脚本、核对固件 hash、解析你贴回来的输出、判断每步是否正确、出错时定位原因；
- **你负责**：在 PowerShell 里粘贴我给的命令（或双击我生成的 `.ps1` 脚本）。

所以下面要准备的工具，是"让你能一条条执行、并把结果贴给我"的最小集合。

## 2. 风险评估：当前流程已避开 initramfs 断联窗口（2026-11-14 更新）

最初设计要经过 initramfs 中转（内存临时系统无 Wi-Fi，必须网线）。**最终固件核对后流程已改为原厂直刷**，
不经过 initramfs，风险大幅下降：

| 阶段 | Wi-Fi 能不能用 | 说明 |
|---|---|---|
| 原厂固件（刷写时） | ✅ 能 | ubiformat 写对侧分区，全程原厂系统在线，SSH 不断 |
| 重启进 LibWrt 后 | ✅ 能 | `99-wifi-firstboot` 首启自动开 `AX3600-Setup`，管理地址 192.168.2.1 |
| 唯一裸露窗口 | ⚠️ 重启瞬间 | 断电/固件异常时无 Wi-Fi——所以刷前必须完成第 6 节全分区备份，并保留官方救砖预案（网线） |

保留的建议：**网线/USB 网卡仍然强烈建议备好**——不是为刷写窗口，而是为了③级救砖（官方修复工具必须网线）。

## 5. 只有 Wi-Fi 时的网络注意事项

1. **AP 隔离必须关闭**：如果这个 Wi-Fi 是访客网络或开了"客户端隔离"，电脑和路由器之间会被阻断（表现为 SSH 连不上但后台网页能开）。确认路由器后台没有开"访客网络/AP 隔离"。
2. **不需要外网**：`ssh`/`scp` 走二层内网，不需要 DNS、不需要出口，断网完全不影响。
3. **Windows 网络位置设为"专用"**：设置 → 网络和 Internet → Wi-Fi → 该网络 → 网络配置文件改为"专用"，避免防火墙策略变化影响。
4. **降级后 IP 是 192.168.31.1，刷完后是 192.168.2.1**：换 IP 后电脑可能缓存旧地址，必要时 `ipconfig /release` + `ipconfig /renew` 或重连 Wi-Fi。
5. **刷机后 SSID 变了**：正式固件起来后 Wi-Fi 名为 `AX3600-Setup`，密码 `AX3600-Setup-9pQ7xM2k`（首启脚本预置，登录后请立刻改）。

## 6. 刷前必做：**全分区备份**（约 15 分钟，必做不是建议）

> 本次刷机流程**不经过 initramfs**（原厂 SSH 里直接 ubiformat 写对侧分区），所以没有"中途断联"窗口；
> 但如果刷写中途断电、写错分区、或新固件起不来又回不去，**全分区备份就是唯一能把机器恢复到"连官方修复工具都恢复不出来的状态"的手段**。
> 特别是：小米官方修复工具**不会覆盖 `0:ART`（无线校准）和 `0:bdata`（SN/MAC/串口标志）**——这两个分区一旦损坏，官方救砖也无能为力，只有你的备份能救。

### 6.1 备份方法（推荐：SSH 流式直传电脑，不占路由器内存）

在 **PowerShell（cmd 兼容模式）** 里逐条执行，`cmd /c` 保证二进制重定向安全（PowerShell 原生 `>` 会把二进制转码损坏，**不要用**）：

```powershell
cd 到你的备份目录
# 先看分区表（把输出贴给我核对）
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 cat /proc/mtd"

# 逐分区备份（一个分区一条命令；编号以你 cat /proc/mtd 的实际输出为准！）
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 dd if=/dev/mtd0 bs=131072" > mtd0_0SBL1.img
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 dd if=/dev/mtd8 bs=131072" > mtd8_ART.img
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 dd if=/dev/mtd9 bs=131072" > mtd9_bdata.img
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 dd if=/dev/mtd10 bs=131072" > mtd10_APPSBL.img
# …… 对 /proc/mtd 里每一个分区都执行一遍，尤其是 rootfs 和 rootfs_1（各 35.75MB）
```

> `dd` 是**只读**操作，不写任何分区，零变砖风险。全盘约 128 MB，Wi-Fi 下约 10–20 分钟。

### 6.2 备份后校验（必做）

```powershell
# 电脑侧算 hash
certutil -hashfile mtd8_ART.img SHA256
# 路由器侧算 hash（与上面对比）
cmd /c "ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1 sha256sum /dev/mtd8"
```

两边一致 = 备份有效。把所有 hash 贴给我，我帮你逐个核对。**备份文件请存到两块不同的介质**（如电脑 + U 盘）。

### 6.3 恢复手段矩阵（按严重程度递增）

| 场景 | 恢复手段 | 需要什么 |
|---|---|---|
| ① 新固件起不来，但原厂分区还在 | 切回原厂启动分区：**仍在原厂系统**里用 `nvram set flag_boot_rootfs=<原值>; nvram commit; reboot`；**已进入 OpenWrt** 则用 `fw_setenv flag_boot_rootfs <原值>; fw_setenv flag_last_success <原值>; fw_setenv flag_boot_success 1; reboot`（与 platform.sh 的升级写法一致，固件已含 fw_setenv） | 能进任一系统的 SSH |
| ② 新固件分区坏了，切回原厂也异常 | 官方分区镜像 `mtd write` 回对应分区（用备份的 rootfs/rootfs_1 镜像；OpenWrt 侧原生 `mtd` 工具，原厂侧无 mtd 工具时需在 OpenWrt 内操作或走③） | 能启动的系统 + 备份 |
| ③ 系统全挂 | **小米官方修复工具 + 网线 + 1.0.17 官方固件**（会重写当前启动分区为官方固件） | 网线（这就是你要换网线机器的原因） |
| ④ `0:ART` / `0:bdata` 损坏（③也救不了） | 从备份 `mtd write` 写回这两个分区，再走 ③ | **只有你的全分区备份能做到** |
| ⑤ 引导层（SBL1/QSEE/APPSBL）损坏 | UART 串口 + 备份镜像写回（接错电压烧 SoC，最后手段） | USB-TTL（3.3V）+ 备份 |

> 结论：**①–③ 官方工具都能兜底（前提是有网线），④ 只有你的备份能救，⑤ 是最终保险**。所以全分区备份 + 官方修复工具 + 网线三样齐备，理论上下限是"永远可以回到官方可用状态"。
